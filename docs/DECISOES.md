| 17 | 2026-09 | Redirect de `/painel` (subdomínio → domínio raiz) é HTML/JS no corpo (status 200) **só em dev**; em produção (`next start`/Vercel) é `NextResponse.redirect()` normal | Bug real, reproduzido: um redirect cross-host emitido pelo `proxy.ts` (middleware) vira loop infinito no servidor de **dev** do Next — `resolve-routes.js` "relativiza" o `Location` comparando contra um `initUrl` montado com o hostname de BIND do servidor (ex. | 27 | 2026-09 | Vercel Blob: autenticação por `storeId`/OIDC em vez de `BLOB_READ_WRITE_TOKEN`, com o token como fallback opcional (`NEXT_PUBLIC_BLOB_UPLOAD_AUTH`) | Testando de verdade contra o projeto de staging: conectar um store **já existente** ao projeto ("Storage → Connect Project") não cria mais nenhum `BLOB_READ_WRITE_TOKEN` — só `BLOB_<PREFIXO>_STORE_ID`/`BLOB_<PREFIXO>_WEBHOOK_PUBLIC_KEY` (a doc confirma depois: token estático só nasce automático quando o store é criado do zero pelo assistente "Create Storage", não quando um store existente é conectado). `put`/`del`/`issueSignedToken` aceitam `storeId` no lugar de `token` (autentica via `VERCEL_OIDC_TOKEN`, que a Vercel injeta/renova sozinho) — `lib/storage/vercel-blob-provider.ts` tenta o token primeiro, cai pro storeId se não achar.
